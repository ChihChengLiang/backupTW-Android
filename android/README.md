# android/ — dev harnesses, not the app shell

Two Gradle modules, neither of which is **the** Phase 4 Android app shell
described in `docs/2026-09-05-decisions-and-roadmap.md`:

- **`app/` (`zkharness`)** — Phase 1's validation harness. Proves the
  OpenACAge Mopro ZK bindings work when loaded and run inside a real
  Android runtime.
- **`wallet/`** — a fixture-driven proof that `core/`'s hand-written Rust,
  exposed through UniFFI, works end-to-end on Android: one screen, four
  sections, no navigation, no storage, no design system. (1) generates a
  `did:key` identity and shows both spellings; (2) parses a bundled
  fixture TWDIW credential offer and trust-list page and runs the three
  issuer-authorization gates; (3) generates an in-memory P-256 key
  (`HolderKey.kt` — real ECDSA signing via the JCA `Signature` API, DER→raw
  `r ‖ s` conversion, same shape real Android Keystore signing will need)
  and builds/signs a real OID4VCI proof JWT; (4) reads and cryptographically
  verifies a bundled fixture TWDIW SD-JWT credential and displays its
  disclosed claims. See `core/src/ffi.rs`'s doc comment for why keys
  throughout are ephemeral/in-memory (Keystore-backed generation, the real
  design, needs a trait/callback boundary this doesn't build yet) and
  `Fixtures.kt` for why nothing here makes a live network call (no TWDIW
  sandbox endpoint is wired up - the three steps are proven independently
  against bundled data, not chained into one continuous live flow).

When Phase 4 starts the real app shell, expect both modules' package
names, `minSdk`, and structure to be revisited from scratch per the open
question in the roadmap doc ("Exact Android minSdk/target SDK, package
name, and module layout within android/ — deferred to Phase 0 execution").
Nothing here should be read as having pre-decided any of that.

## `wallet/`: regenerating the native library + bindings

```
cd core
cargo ndk -t aarch64-linux-android build --release --lib   # real devices
cargo ndk -t x86_64-linux-android build --release --lib    # emulator
cargo run --bin uniffi-bindgen -- generate \
  --library target/aarch64-linux-android/release/libbackuptw_core.so \
  --language kotlin --out-dir /tmp/core-bindings
cp /tmp/core-bindings/uniffi/backuptw_core/backuptw_core.kt \
  ../android/wallet/src/main/kotlin/uniffi/backuptw_core/
cp target/aarch64-linux-android/release/libbackuptw_core.so \
  ../android/wallet/src/main/jniLibs/arm64-v8a/
cp target/x86_64-linux-android/release/libbackuptw_core.so \
  ../android/wallet/src/main/jniLibs/x86_64/
```

Gitignored (see `.gitignore`), same as `app/`'s — regenerate, don't expect
them to already be there. `android.useAndroidX=true` in
`gradle.properties` is required (Compose's AndroidX dependencies fail
`checkDebugAarMetadata` without it) and easy to lose if `gradle.properties`
ever gets regenerated by tooling.

```
cd android
gradle :wallet:assembleDebug
adb install -r wallet/build/outputs/apk/debug/wallet-debug.apk
```

Confirmed working 2026-09-05: launches with no crash, all four sections
produce real (non-crashing, non-placeholder) output on the x86_64 API 34
emulator - identity generation, the three-gate offer evaluation (all pass
against the bundled fixture issuer), a real signed three-segment proof
JWT, and a verified fixture credential with its disclosed claims shown.

⚠️ **Testing note**: this screen scrolls, and each button's on-screen
position moves down as earlier sections' results are added above it. A
tap at a coordinate that hit a button before the screen had content will
silently miss (or hit a different button) after it does - `adb shell
uiautomator dump` before each tap, or scroll to a known position first,
rather than reusing coordinates across state changes.

## `app/` (zkharness): regenerating the native library + bindings

The `app/src/main/jniLibs/*/lib*.so` and
`app/src/main/kotlin/uniffi/mopro/mopro.kt` files in this module are
copied from a manual build against a clean `ethereum/zkID` checkout with
the `backupTW-iOS/Native/OpenACAge/` overlay applied — see that
directory's own `README.md` for the exact commit/overlay, and
`docs/2026-09-05-session-checkpoint.md` for the full command sequence
(`circom` compile, `age_assets` native run, `cargo build --release --bin
android` via `cargo-ndk`). Nothing in that chain is automated by this
Gradle module yet. They're gitignored (see `.gitignore`) rather than
committed — regenerate them, don't expect them to already be there.

`cargo-ndk`/`mopro-ffi`'s Android build only copies the final crate's own
`.so` into `jniLibs/` — it does **not** pick up `libwitnesscalc_jwt_2k.so`
/ `libwitnesscalc_show.so`, which `ecdsa-spartan2`'s `build.rs` also
builds (dynamically linked, loaded at runtime) but leaves under
`target/<abi>/release/build/ecdsa-spartan2-*/out/witnesscalc/package/lib/`.
Copy those into `jniLibs/<abi>/` too, or `setupJwtKeys`/`setupShowKeys`
fails fast with a generic-looking `SynthesisError`.

`mopro.kt` as generated by UniFFI 0.29 needs one hand-patch: each
`ZkProofException` subclass declares a `val message: String` constructor
property *and* a separate `override val message` getter, which is a
genuine name collision in Kotlin (not a version-specific strictness
change) — mark the constructor property `override` and drop the
redundant getter block. See git history for the exact patch if
regenerating from scratch.

### Running the check

You need an x86_64 API 34 emulator running (`avdmanager create avd -n dev
-k "system-images;android-34;google_apis;x86_64"` once, then `emulator
-avd dev -no-window -no-audio -gpu swiftshader_indirect`) — a plain host
JVM can't load an Android NDK `.so` (different libc/dynamic linker), so
this genuinely needs a real Android runtime, not just `./gradlew test`.

```
cd android
gradle assembleDebug
adb install -r app/build/outputs/apk/debug/app-debug.apk
```

The r1cs circuit files (`jwt_2k.r1cs` renamed to `jwt.r1cs`,
`show.r1cs`) need to land at
`<internal files dir>/circom/build/{jwt/jwt_js,show/show_js}/*.r1cs`
before first launch. Use **internal** storage (`run-as` + `cp` from a
`/data/local/tmp` staging push), not external
(`getExternalFilesDir`/`Android/data/<pkg>`) — files pushed into
`Android/data/<pkg>` via plain `adb shell mkdir`/`push` end up owned by
`shell` and aren't visible to the app's own process under scoped
storage's per-app FUSE isolation, even though raw `ls`/POSIX permissions
look fine. Concretely:

```
PKG=tw.bonds.backuptw.zkharness
adb push jwt_2k.r1cs /data/local/tmp/jwt.r1cs
adb push show.r1cs /data/local/tmp/show.r1cs
adb shell run-as "$PKG" mkdir -p files/circom/build/jwt/jwt_js files/circom/build/show/show_js
adb shell run-as "$PKG" cp /data/local/tmp/jwt.r1cs files/circom/build/jwt/jwt_js/jwt.r1cs
adb shell run-as "$PKG" cp /data/local/tmp/show.r1cs files/circom/build/show/show_js/show.r1cs
```

Then:

```
adb shell am force-stop "$PKG"   # if it was already running once and failed
adb logcat -c
adb shell am start -n tw.bonds.backuptw.zkharness/.MainActivity
adb logcat -s ZkHarness:*
```

Expect a single `ZkHarness` log line: `RESULT: PASS (prepare=...ms
show=...ms)` or `RESULT: FAIL: <reason>`. Confirmed passing 2026-09-05 on
the x86_64 API 34 emulator: `prepare=7549ms show=237ms` (setup, run once
per fresh install, took ~22s for jwt / ~0.24s for show).
