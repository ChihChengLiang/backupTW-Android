# android/ — Phase 1 validation harness (not the app shell)

This is **not** the Phase 4 Android app shell described in
`docs/2026-09-05-decisions-and-roadmap.md`. It exists only to satisfy Phase
1's actual exit criterion: proving the OpenACAge Mopro bindings work when
loaded and run inside a real Android runtime (a plain host JVM can't load
an Android NDK `.so` — different libc/dynamic linker — so this needs an
emulator or device, not just a JVM unit test).

`app/` is a single-Activity app whose `MainActivity` replays the exact
fixed test vector `backupTW-iOS/Native/OpenACAge/age_assets.rs` uses
(same disclosure salt, same fixed nonce, same cutoff date) through the
generated Kotlin bindings, and logs a pass/fail verdict. There is no UI,
no navigation, no design system — none of that is in scope here.

When Phase 4 starts the real app shell, expect this module's package name,
`minSdk`, and structure to all be revisited from scratch per the open
question in the roadmap doc ("Exact Android minSdk/target SDK, package
name, and module layout within android/ — deferred to Phase 0 execution").
Nothing here should be read as having pre-decided any of that.

## Regenerating the native library + bindings

The `app/src/main/jniLibs/*/lib*.so` and
`app/src/main/kotlin/uniffi/mopro/mopro.kt` files in this module are
copied from a manual build against a clean `ethereum/zkID` checkout with
the `backupTW-iOS/Native/OpenACAge/` overlay applied — see that
directory's own `README.md` for the exact commit/overlay, and
`docs/2026-09-05-session-checkpoint.md` for the full command sequence
(`circom` compile, `age_assets` native run, `cargo build --release --bin
android` via `cargo-ndk`). Nothing in that chain is automated by this
Gradle module yet. They're gitignored (see `.gitignore`) rather than
committed — regenerate them, don't expect them to already be there.

`cargo-ndk`/`mopro-ffi`'s Android build only copies the final crate's own
`.so` into `jniLibs/` — it does **not** pick up `libwitnesscalc_jwt_2k.so`
/ `libwitnesscalc_show.so`, which `ecdsa-spartan2`'s `build.rs` also
builds (dynamically linked, loaded at runtime) but leaves under
`target/<abi>/release/build/ecdsa-spartan2-*/out/witnesscalc/package/lib/`.
Copy those into `jniLibs/<abi>/` too, or `setupJwtKeys`/`setupShowKeys`
fails fast with a generic-looking `SynthesisError`.

`mopro.kt` as generated by UniFFI 0.29 needs one hand-patch: each
`ZkProofException` subclass declares a `val message: String` constructor
property *and* a separate `override val message` getter, which is a
genuine name collision in Kotlin (not a version-specific strictness
change) — mark the constructor property `override` and drop the
redundant getter block. See git history for the exact patch if
regenerating from scratch.

## Running the check

You need an x86_64 API 34 emulator running (`avdmanager create avd -n dev
-k "system-images;android-34;google_apis;x86_64"` once, then `emulator
-avd dev -no-window -no-audio -gpu swiftshader_indirect`) — a plain host
JVM can't load an Android NDK `.so` (different libc/dynamic linker), so
this genuinely needs a real Android runtime, not just `./gradlew test`.

```
cd android
gradle assembleDebug
adb install -r app/build/outputs/apk/debug/app-debug.apk
```

The r1cs circuit files (`jwt_2k.r1cs` renamed to `jwt.r1cs`,
`show.r1cs`) need to land at
`<internal files dir>/circom/build/{jwt/jwt_js,show/show_js}/*.r1cs`
before first launch. Use **internal** storage (`run-as` + `cp` from a
`/data/local/tmp` staging push), not external
(`getExternalFilesDir`/`Android/data/<pkg>`) — files pushed into
`Android/data/<pkg>` via plain `adb shell mkdir`/`push` end up owned by
`shell` and aren't visible to the app's own process under scoped
storage's per-app FUSE isolation, even though raw `ls`/POSIX permissions
look fine. Concretely:

```
PKG=tw.bonds.backuptw.zkharness
adb push jwt_2k.r1cs /data/local/tmp/jwt.r1cs
adb push show.r1cs /data/local/tmp/show.r1cs
adb shell run-as "$PKG" mkdir -p files/circom/build/jwt/jwt_js files/circom/build/show/show_js
adb shell run-as "$PKG" cp /data/local/tmp/jwt.r1cs files/circom/build/jwt/jwt_js/jwt.r1cs
adb shell run-as "$PKG" cp /data/local/tmp/show.r1cs files/circom/build/show/show_js/show.r1cs
```

Then:

```
adb shell am force-stop "$PKG"   # if it was already running once and failed
adb logcat -c
adb shell am start -n tw.bonds.backuptw.zkharness/.MainActivity
adb logcat -s ZkHarness:*
```

Expect a single `ZkHarness` log line: `RESULT: PASS (prepare=...ms
show=...ms)` or `RESULT: FAIL: <reason>`. Confirmed passing 2026-09-05 on
the x86_64 API 34 emulator: `prepare=7549ms show=237ms` (setup, run once
per fresh install, took ~22s for jwt / ~0.24s for show).
